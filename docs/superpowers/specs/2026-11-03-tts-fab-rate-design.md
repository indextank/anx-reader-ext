# 阅读页 TTS 快捷控件与倍速设计

日期：2026-11-03

## 目标

重构书籍阅读界面朗读时的浮动快捷控件，在保留播放/暂停和停止功能的基础上，提供六档单选倍速，并让选择实时作用于当前朗读。

## 范围

- 修改 `lib/widgets/reading_page/tts_fab.dart` 的展开快捷栏。
- 复用 `TtsHandler.rate`、现有 `ttsRate` 偏好设置和现有引擎倍速实现。
- 增加针对快捷栏和倍速交互的自动化测试。
- 不修改完整朗读设置面板，不新增引擎，不改变上一句/下一句在其他入口的功能。

## 界面与交互

展开后的快捷栏依次只显示：

1. 播放/暂停：根据 `TtsStateEnum` 显示对应图标，沿用 `audioHandler.play()` / `pause()`。
2. 倍速：按钮显示当前实际倍速，格式为 `0.6×`、`1.0×` 等，并提供展开菜单的视觉与语义提示。
3. 停止：沿用 `audioHandler.stop()`，停止后收起快捷栏。

移除快捷栏中的上一句和下一句按钮。右侧独立关闭按钮仍只负责收起/展开，不停止朗读。

点击倍速按钮弹出菜单，标题使用现有本地化文案 `ttsRate`。菜单提供且仅提供以下单选项：

- `0.6×`
- `1.0×`
- `1.5×`
- `1.6×`
- `1.8×`
- `2.0×`

当前值等于某一选项时，仅该项选中。选择后立即应用倍速并关闭菜单；不自动收起整个快捷控件，不切换播放/暂停状态。历史偏好值若不在六档内，按钮仍显示实际值，菜单不选中任何项，不擅自改写设置。

菜单在屏幕空间不足时由 Flutter 菜单布局调整位置，避免超出屏幕；快捷栏继续使用现有阅读页设计令牌、卡片和图标按钮风格。

## 状态与数据流

倍速选择调用现有 `TtsHandler.rate = value`，由当前 `BaseTts` 实现处理并持久化到 `Prefs().ttsRate`。快捷栏从同一处理器读取当前值，选择后刷新自身显示，不建立第二份倍速状态。

### 系统 TTS

沿用 `SystemTts.rate` 的现有行为：保存新值并重启当前句，使新倍速实时生效。此次不改动该引擎实现。

### 在线 TTS

沿用 `OnlineTts.rate` 的现有行为：

- 支持服务端倍速参数的引擎：保存新值、使待播放音频缓存失效，后续音频按新倍速请求。
- 不支持服务端倍速参数的引擎（例如 MiMo）：同时立即调用播放器倍速接口，让当前音频实时变速，并刷新后续音频。

此次不改动在线引擎实现。六档数值均处于现有播放器倍速限制 `0.5–2.0` 内。

## 异常与边界

- 倍速菜单只在朗读处于 playing 或 paused、快捷控件可交互时出现。
- 暂停状态选择倍速后仍保持暂停；恢复朗读时使用新值。
- 停止朗读时按现有逻辑收起快捷栏，倍速菜单随所属控件消失。
- 引擎自身的异步设置失败继续沿用现有日志与容错，不在快捷栏新增错误提示或重试机制。
- 不引入新的倍速档位、自定义倍速、滑块或循环切换手势。

## 测试与验收

采用组件测试覆盖：

1. 展开后只有播放/暂停、倍速、停止三个主要操作，不再出现上一句/下一句。
2. 倍速菜单展示六个指定单选项，当前值正确选中。
3. 逐项选择代表性档位后，`TtsHandler.rate` 与 `Prefs().ttsRate` 更新，按钮显示新值，菜单关闭。
4. 播放中选择不触发暂停或停止；暂停中选择不触发播放或停止。
5. 非六档历史值不造成错误选中，选择新档后正常归一到六档。
6. 停止与关闭按钮原有行为不回退。

运行相关测试、格式化及静态分析。若现有测试环境无法实例化全局音频 handler，则为快捷栏提取可注入的轻量控制接口，生产环境仍委托现有单例，测试使用假实现；不为此改动引擎架构。

## 完成标准

用户能在阅读页展开 TTS 快捷控件，直接从六个单选项中选择倍速，并立即看到当前值更新；朗读引擎通过上述既有路径应用新倍速，播放/暂停和停止行为保持正常，快捷栏不再显示上一句/下一句。
